<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client -> Google Apps Script Web App | Anonymous (`Anyone` access) public `/exec` endpoint reachable by anyone who reads the client bundle; untrusted form input crosses here. |
| Apps Script -> Google Sheet | The Sheet is encapsulated inside the script (D-02); the frontend never references it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering / Denial of Service | Public `/exec` endpoint (anonymous POST) | low | accept | Same public-endpoint trust boundary the prior Formspree integration already had (endpoint id was visible in the bundle). No honeypot / rate limiting for launch per D-07; Apps Script consumer-account quotas provide an implicit ceiling. |
| T-02-02 | Information Disclosure | `appsScriptUrl` embedded in the client bundle | low | accept | The URL is not a secret credential (D-07) — public by nature, like the previous Formspree id. The Sheet id stays inside the script (D-02), so exposure of the URL does not reveal the data store. |
| T-02-03 | Tampering | CSV/formula injection into the Sheet via a `name`/`email` value beginning with `=`/`+`/`-`/`@` | low | accept | Only the sheet owner views rows; no REG requirement covers sanitization. Any mitigation (apostrophe-prefixing a leading formula char) belongs to the Apps Script tier, outside this repo's frontend scope. Noted for awareness. |

**Package Legitimacy:** Not applicable — this phase installs no npm/pip/cargo packages (only edits existing `fetch` code and adds a plain-string config module). No `T-02-SC` supply-chain checkpoint required.
</threat_model>
