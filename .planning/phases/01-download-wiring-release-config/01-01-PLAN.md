<objective>
Wire the post-registration download to the correct, signed macOS build on the correct repo, move the release URL into a single config module so future releases are zero-edit, present Windows as a safe disabled "coming soon" state, and label the macOS button so Intel-Mac users are not misled.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → GitHub Releases | The download href sends the user off-site to GitHub-hosted release assets; the URL must point at the official repo. |
| build config → rendered page | The download URL originates in src/lib/downloads.ts and is compiled into the static page; a wrong value ships to every visitor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | macDownloadUrl in src/lib/downloads.ts | high | mitigate | URL is centralized in one config module pointing at the official Arthium-Org/stock-plan-companion-app latest release; unit test (Task 1/2) locks the exact string so a typo/wrong-repo drift fails CI. App DMG is code-signed (arm64). |
| T-01-02 | Spoofing | GitHub latest-release redirect | low | accept | GitHub serves release assets over HTTPS from the verified repo; no additional control needed for a public marketing download link. |
| T-01-03 | Denial of Service | Windows placeholder control | medium | mitigate | Rendered as a disabled non-interactive element with no href, so it cannot dead-link/404 or send users to a broken destination (D-05). |
| T-01-04 | Information Disclosure | version visibility | low | accept | Version number intentionally not surfaced (D-08); no secrets involved (static site, no backend). |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this phase — only local source edits and a test file; nothing to audit. |
</threat_model>
