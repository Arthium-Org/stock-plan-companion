<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → external destinations | Clicking a link navigates the user off-site (GitHub) or opens a mail client (mailto). A wrong destination sends the user somewhere unintended. |
| build-time config → prerendered HTML | `appRepo`/`repoUrl` is inlined into the static HTML at build; a wrong constant value silently ships to every visitor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | GitHub hrefs in +page.svelte | medium | mitigate | Bind hrefs to the single `repoUrl` constant (Task 2) and assert its exact value in a unit test (Task 1), preventing the stale/wrong-repo drift this phase fixes. |
| T-03-02 | Information disclosure | footer Contact mailto | low | mitigate | Replace the personal Gmail with the role address `contact@arthium.org` (Task 2); grep gate confirms the old address appears nowhere. |
| T-03-03 | Spoofing | external GitHub anchors | low | accept | Links are same-origin-authored to a known GitHub org over HTTPS with `rel="noopener noreferrer"` already present; no user-supplied URL is involved, so no dynamic-URL injection surface exists. |
</threat_model>
