## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] Preserved `$lib/downloads` wiring instead of the prototype's hardcoded download links**
- **Found during:** Task 1 (promoting `new-12345/+page.svelte` to `/`)
- **Issue:** The prototype being promoted (`new-12345/+page.svelte`) used a hardcoded `downloadLinks` object with version-pinned URLs and a `// TODO: update these direct-download URLs on EVERY release` comment. The page it was replacing (`src/routes/+page.svelte`) already had this exact anti-pattern fixed in a prior phase: it imports `macDownloadUrl` and `windowsAvailable` from `$lib/downloads.ts` (a tested module — see `src/lib/downloads.test.ts` — encoding decisions D-01/D-02/D-04/D-05/D-06/D-07 from STATE.md, including a GitHub "latest release" URL that requires zero code edits per release, and a disabled Windows button so it can never 404). A verbatim copy would have silently reintroduced the exact "Hardcoded Download Links in Form Handler" anti-pattern documented in this project's CLAUDE.md.
- **Fix:** Kept the `import { macDownloadUrl, windowsAvailable } from '$lib/downloads';` import and the corresponding markup (macOS Apple Silicon download link with tooltip, disabled "Windows (coming soon)" button) from the page being replaced. Did not carry over the prototype's `downloadLinks` state variable, its TODO comment, or its hardcoded URLs.
- **Files modified:** `src/routes/+page.svelte`
- **Verification:** `grep -n "macDownloadUrl\|windowsAvailable" src/routes/+page.svelte` confirms both are imported and used; `npm run build` succeeds; `grep -rn 'downloadLinks' src/` returns nothing (hardcoded prototype pattern fully removed).
- **Committed in:** `43a8bdc` (Task 1 commit)
